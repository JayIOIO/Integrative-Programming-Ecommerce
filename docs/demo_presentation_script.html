Code Location in VS Code server/server.js lines 107–114 (signup handler) & lines 138–151 (login handler)
Spoken Script "Starting with Authentication: notice when I type an invalid email or short password, our client-side Zod schema in schemas.ts catches it instantly on blur before any network request is sent.

Behind the scenes in server.js:
  1. When the user registers, we hash the password with bcrypt using 10 salt rounds (bcrypt.hash). Plain passwords are never stored in MySQL.
  2. During login, bcrypt.compare verifies the entered password against the stored database hash.
  3. Once verified, the server issues a JSON Web Token (JWT) signed with our secret key. It contains the user's ID, name, and email and expires in 24 hours.
  4. The client stores this token in localStorage, attaching it to the Authorization: Bearer header on all protected API calls."

Code Location in VS Code server/server.js lines 300–353 (createOrderHandler transaction)
Spoken Script "Now for the checkout process — this is the most critical part of our system architecture.

Notice two important engineering decisions we made:
  1. Server-Side Price Validation: The server completely ignores prices sent by the browser. It recalculates the total directly from current database product records to prevent client-side price tampering.
  2. ACID MySQL Transactions with Concurrency Control: In server.js, you can see connection.beginTransaction(). For every item, we execute SELECT ... FOR UPDATE. This locks the database row so two concurrent buyers cannot buy the last available item simultaneously.
The server inserts the order header into checkout_orders, records item snapshots into order_items, and decrements stock in products. If any item is out of stock, it executes rollback(). If everything succeeds, it executes commit(). All or nothing."

🎯 Professor Oral Defense Cheat Sheet (Fast Answers)

Likely Professor Question Precise Technical Answer to Give
Why use Database Transactions during checkout? "To guarantee the Atomicity property of ACID. If product stock deduction fails after inserting the order header, connection.rollback() cancels everything so our database is never left in an inconsistent state."
What does FOR UPDATE do? "It applies an exclusive row-level lock in MySQL during the checkout transaction. This prevents Race Conditions and overselling when two users try to purchase the last unit at the exact same millisecond."
Can a user spoof product prices from Chrome DevTools? "No. Our backend enforces Server-Side Price Calculation. It ignores client prices and re-reads the official price directly from the MySQL products table."
How does login verify a password if it's hashed? "We use bcrypt.compare(). It hashes the entered password using the salt stored in the hash and compares the result, without ever needing to decrypt the stored hash."
Why use JWT instead of traditional sessions? "JWTs are stateless and self-contained. The server does not need to maintain session memory or hit a session database for every request; it simply verifies the cryptographic signature with our secret."
How do you prevent SQL Injection? "All SQL queries use parameterized prepared statements with ? placeholders. User input is treated strictly as data literals, never as executable SQL commands."
